Scheduler: Multilevel grouping — новый рендеринг заголовков. Ниже — дословные CSS-правила из PR (base/scheduler/views/_index.scss, коммит 30431804bf), применённые к реальной DOM-структуре, которую генерирует GroupPanelVerticalNode. Это не полный виджет, а изолированное воспроизведение механики раскладки: «как сейчас в PR» рядом с «как было бы с фиксом».

#1 · Вложенные не-листовые строки теряют горизонтальную раскладку при 3+ уровнях HIGH

Базовое правило применяет flex-direction: column к любой вложенной строке (селектор-потомок), а иерархический оверрайд возвращает row только строкам нулевого уровня — через дочерний комбинатор >: 

/* _index.scss:307  — потомок: срабатывает на ВСЕХ уровнях */
.dx-scheduler-group-flex-container .dx-scheduler-group-row { flex-flow: column nowrap; }

/* _index.scss:340  — только ПРЯМЫЕ потомки (>): уровень 0 */
.dx-scheduler-group-flex-container-hierarchical > .dx-scheduler-group-row { flex-flow: row nowrap; }

У обоих селекторов специфичность одинаковая (2 класса), но иерархический блок идёт позже → на уровне 0 побеждает row. Для строк уровня 1+ иерархического правила нет, остаётся column базового → заголовок узла встаёт над детьми, а не сбоку. Срабатывает при maxDepth > 1, то есть и на обычной декартовой группировке по 3 ресурсам (group_panel_vertical.tsx).

Дерево: Регион → Здание → Комната (равномерная глубина 3).

Как в PR (уровень 1 = column)
С фиксом (row на всех уровнях)
Слева заголовки «Здание N1/N2/S1» — это широкие полосы над своими комнатами (сломанная вложенность). Справа они стоят колонкой слева от комнат, как и ожидается от иерархического заголовка.

#2 · «Короткий» лист при неравномерной глубине зажат в ширину левой колонки MED

Ветка мельче самой глубокой (здание без комнат) рендерится как единственный заголовок в строке → срабатывает правило :only-child и фиксирует ширину в $scheduler-left-column-width: 

/* _index.scss:379 */
.dx-scheduler-group-flex-container-hierarchical > .dx-scheduler-group-row
  > .dx-scheduler-group-header.dx-scheduler-group-header-leaf:only-child {
  flex: 0 0 auto; width: 100px; min-width: 100px;
}

Дерево: Здание A → (Комната A1, A2) и Здание B (без комнат).

Как в PR (B зажат в 100px)
Вариант: B на всю ширину
Слева «Здание B» — узкий блок в 100px с пустотой справа. Спорно с точки зрения дизайна (возможно, так и задумано), поэтому severity — MED: стоит просто посмотреть и решить.

#3 / #4 · Доступность (не визуально — по DOM) MED

DOM, который выдаёт GroupPanelVerticalNode (строки 51–52):

<div class="dx-scheduler-group-header ..."
     title={node.text}
     role="rowheader"          // #4: role без предка role=row/grid/table → связь недействительна для скринридеров
     aria-label={node.text}>  // #3: жёстко перекрывает доступное имя из resourceCellTemplate
  {cellTemplate ? <PublicTemplate .../> : <div class="...-content">{node.text}</div>}
</div>
  • #3 — aria-label={node.text} задан безусловно: при кастомном resourceCellTemplate доступное имя всё равно = сырой текст ресурса. Ставить только без шаблона.
  • #4 — role="rowheader" на <div> без предка role="row"/"rowgroup"/"grid"/"table" не образует заголовочной связи. Либо добавить роли контейнерам, либо убрать.
