PR #34257 — collector tooltip shows stale appointment data (regression repro)

Both frames run the same scenario with _newAppointments: true: 3 appointments at 8:00–9:00, maxAppointmentsPerCell: 1, so two of them are hidden behind the “2” collector. The button calls scheduler.updateAppointment() and changes the hidden “Appointment 2” end time from 9:00 to 8:30 — the collector item count does not change.

  1. Click “1. Change hidden appointment” in both frames.
  2. Click the “2” collector button in both frames.
  3. Compare the time shown for Appointment 2 in the tooltip.
Left (base, before PR): tooltip shows the updated time 8:00 AM - 8:30 AM ✔
Right (PR #34257 head): tooltip still shows 8:00 AM - 9:00 AM ✘ — the collector is matched by position + item count only, so it is not rerendered and keeps stale view models.

Cause: get_view_model_diff.ts — the new collector match no longer consults isAppointmentDataChanged(), and needToUpdateItems fires only when items.length changes. Same-count data updates (e.g. time edits) leave the collector—and the tooltip data built from its stale items—unrefreshed. Jest repro: base commit a88c55a4 passes, PR head cd2ed9d6 fails.
