Scheduler: иерархический ресурс — дефолтная форма предлагает родительские узлы

Тема

Один ресурс с parentIdExpr, группировка по нему же. Форма встречи не кастомизирована: ни onAppointmentFormOpening, ни editing.form. Сборка — 26.2.0 из ветки feature/scheduler-multilevel-grouping/main (в main фичи нет).

  1. Двойной клик по Upgrade Personal Computers (строка Samantha Bright).
  2. Открыть редактор Employee: в списке есть 🏢 Room 1 и 🏢 Room 2 — родительские узлы, которые не являются листьями группировки.
  3. Снять тег Samantha Bright, выбрать 🏢 Room 1, нажать Save.
  4. Встреча исчезает из всех групп. Ни ошибки, ни сообщения валидации.

Панель со списком читает тот же массив, на который подписан Scheduler, — видно, что запись никуда не удалилась, просто assigneeId: ["room-1"] не совпадает ни с одним листом группировки, а группы строятся только по листьям (collectGroupLeaves в group_utils.ts).
