PR #34254 — Scheduler appointmentDragging: two repro scenarios

P1 (regression): with two schedulers on a page and no appointmentDragging.group, dropping an appointment onto the other scheduler moves it inside the source scheduler. The PR removed the isSameScheduler containment check in appointment_drag_controller.ts > onDragEnd; the drop should be cancelled.

P2 (contract miss): for cross-component drags (appointmentDragging.group shared) the onDragEnd event no longer carries toItemData — the old implementation (m_appointment_drag_behavior.ts:143) always set it before invoking the callback.

Steps (both frames run the same scenario):

  1. P1 (default radio): drag Appointment 1 from Scheduler A and drop it on any cell of Scheduler B. Left (PR): the appointment moves inside Scheduler A and red onAppointmentUpdating/Updated lines appear in the log. Right (old impl reference): the appointment snaps back, log stays empty.
  2. P2 radio: drag Appointment 1 from A onto B. Compare the onDragEnd — toItemData log line: left (PR) shows undefined (red), right shows the drop dates (green).
